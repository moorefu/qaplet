## 拆分原则

- 01 用可运行的 M2 空实例与 M1 兼容闭环承接必要的生命周期/驱动保护重构，先于所有产品资源接入；不单独派发无行为交付的重构票。
- 02–05 是独立的 Ubuntu producer → 真实 OS 操作 → 分发消费/原始证据闭环，可与 01 并行。它们产出 backend 决策事实，不等于产品支持已经验收。
- C Host 子集也是完整产品入口；先让 C 用户执行、取消和清理实际任务/进程，再添加 JS wrapper，避免一张票同时横跨所有新层。
- 每个资源提供者首次出现时就实现相应硬限额、结果保留和最小安全 stop/close/quiesce/destroy；19/20 负责跨资源组合与故障边界，不是首次实施预算或关闭安全。
- 每张产品票须有自身公开接口正负验收及适用 Cross/Full；24–27 负责完整矩阵、增强长测和严格重放，不代替此前平台检查。
- 未实现子集不得用成功 stub、隐式 fallback 或过大的支持声明提供。完整默认与最终能力仍以父规格为准。
- 只记录真实阻塞，独立任务不因共享文件或编号相邻而串行。实际工作领取所有 blocker 已完成的 frontier。
- 全部产品构建在 Ubuntu，复用仓库既定输入、缓存和证据方式；其他宿主消费供应制品。没有新增 M3/M4/M8 或发布镜像前置。

## 已确认编号方案

1. **M2 Runtime 的可选创建与兼容生命周期**。阻塞：无。交付：纯 C Host 显式创建 M2 空实例，查询有效配置、分步推进并安全 close/quiesce/destroy，同时继续使用旧 M1 SDK 合同。必要的 owner 驱动保护和原生保留边界重构随这条闭环先落地。

2. **唤醒与 Socket 等待的真实 OS 探针**。阻塞：无。交付：Ubuntu 生成并分发原生探针，在真实目标验证跨线程唤醒、Socket readiness/错误/关闭及无丢唤醒所需事实，产出可消费的 backend 选择证据。

3. **Pipe 与借用标准流的可取消接入探针**。阻塞：无。交付：以真实 pipe、文件、标准流及别名 fixture 验证有界读写、取消、关闭和共享状态影响，为 stdio backend 提供可复验接入矩阵。

4. **子进程参数、stdio 与继承隔离探针**。阻塞：无。交付：真实启动直接子进程，观察 argv/env/cwd、三路 stdio、退出/reap 和内部句柄隔离，收口 ProcessHost 的 OS 行为。

5. **真实终端租约、resize 与 Console 文本探针**。阻塞：无。交付：在受控 PTY/ConPTY 和真实标准句柄路由中验证模式恢复、尺寸通知与 UTF-8/VT 子集，给出 Console 与二进制流的实际能力边界。

6. **等待中的 Runtime 接收事件与停止**。阻塞：01、02。交付：C Host 使用 run_once/run 等待外部 Qaplet Event；生产者投递、释放保活令牌或请求 stop 后 owner 可靠醒来，旧 pump 继续不主动等待。

7. **一次 timer 推进 TLA 与自然退出**。阻塞：06。交付：JS/C 创建一次 timer，run_once 按最近 deadline 等待，入口 await 被推进；timer ref/unref 和取消参与自然退出及执行期限。

8. **重复 timer、immediate 与检查点轮转**。阻塞：07。交付：重复 timer、immediate 和业务事件有界轮转，完整 jobs 检查点、稳定顺序、ref/unref 与跨 pump 账本共同成立。

9. **宿主自有事件循环的原生通知接入**。阻塞：06。交付：C Host 通过可选 HostNotify 唤醒自己的循环，再在 owner 分步驱动 Runtime；内部等待仍由独立 waker 保证。

10. **纯 C Host 的有界原生工作闭环**。阻塞：06。交付：C Host 注册命名处理器，提交真实有界文件读取任务，等待并复制结果；运行中的任务可安全跨 close 保留到原生退出。

11. **任务取消竞争、结果 release 与容量保留**。阻塞：10。交付：C Host 对排队及运行任务取消，按确定顺序取得唯一终态；复制/释放结果后，物理未退出任务仍安全占额。

12. **JS 命名工作、Promise 与取消闭环**。阻塞：08、11。交付：JS 经 qaplet:work 调用 C Host 处理器，获得任务 Promise、取消与结果；完成交付加入统一检查点调度。

13. **纯 C Host 的显式 spawn 与退出观察**。阻塞：04、06。交付：C Host 以显式路径和复制的 argv/env/cwd 启动直接子进程，等待实际退出并回收；先完成明确 stdio 模式下的最小闭环。

14. **直接子进程取消、回收与关闭竞争**。阻塞：13。交付：C Host 明确取消直接子进程并观察实际终止/reap，正常退出、重复取消、stop 和 close 竞争均保留唯一责任。

15. **子进程三路有界字节 I/O 与 EOF**。阻塞：03、11、13。交付：C Host 使用默认 pipe stdio 并发读 stdout/stderr、写 stdin，取得短读写、背压、EOF 和退出后的剩余输出。

16. **JS Process 与 stdio 的完整异步闭环**。阻塞：12、14、15。交付：JS 经 qaplet:process 启动、读写、取消并观察直接子进程，分别等待退出与 stdio 结束，在自然退出中保留剩余数据。

17. **标准 stdio 的显式安全接入**。阻塞：12、15。交付：C Host 显式接入真实标准流，JS/C 通过统一有界字节操作读取和写入；默认创建不改变宿主标准流。

18. **TTY 租约、resize 与 Console UTF-8**。阻塞：05、17。交付：JS/C 在明确所有权下修改终端模式、观察尺寸变化并使用已验证的 Console 文本/VT 子集，退出路径恢复原模式。

19. **跨资源预算、POD 快照与终止首因**。阻塞：09、16、18。交付：宿主用小公开额度混合提交不同资源，能看到真实拒绝、占用和峰值，并区分操作错误、接受后 wake 故障和永久终止。

20. **组合资源的停止与两阶段清理**。阻塞：09、16、18。交付：同一 Runtime 同时持有任务、timer、进程、stdio/TTY 和宿主通知时，stop 到 close/quiesce/destroy 的所有权屏障一致且可证明。

21. **CLI 异步运行与入口结果保存**。阻塞：20。交付：最小 CLI 使用 M2 Runtime 运行 timer、Process 和 stdio，入口完成后继续 ref 资源，正常结束后输出保存的入口结果。

22. **CLI 中断交接与清理超时报告**。阻塞：21。交付：受支持 SIGINT/SIGTERM、Windows Ctrl+C 唤醒并协作停止 CLI，恢复终端、启动 child 回收，并如实报告 5 秒原生清理等待耗尽。

23. **完整 SDK 分发与包外 C Host 示例**。阻塞：19、22。交付：Ubuntu 产生完整 M2 CLI/静态 SDK 和包外纯 C Host 示例，示例同时演示命名工作、宿主循环通知、进程/stdio 和安全关闭。

24. **五原生目标的合同矩阵与生命周期**。阻塞：23。交付：五个原生目标消费同一供应产品，完整重放 M1/M2 适用合同、真实 backend 和各目标生命周期/混合异步用例。

25. **实际 ARM64 64K 的新合同与清理验收**。阻塞：23。交付：当前 M2 产品在真实 65536 页 Linux ARM64 内核中重放公开合同、backend 与循环；原生优先，以固定完整系统 guest 补缺。

26. **Linux/Windows Full 长测与资源稳定性**。阻塞：23。交付：Linux/Windows 各实际运行 10,000 次混合生命周期及 1 小时 idle/负载/取消交替长测，证明资源有限且退出责任不累积。

27. **M2 严格证据入口与最终集成判定**。阻塞：24、25、26。交付：只读消费完整供应原件，独立核对当前 M2 功能矩阵、平台、次数和长测，以及 M1/M0 回归，给出可复验的通过或阻断结论。

## 初始 frontier 与后续并行

- 初始 01、02、03、04、05 均无 blocker；01 的重构不阻塞独立探针。
- 01、02 完成后可推进 06，再分出 timer（07→08）、HostNotify（09）、原生任务（10→11）以及取得 04 结果后的 Process（13→14）。
- 12 和 15 汇合必要接口，分别推进 JS Process（16）和标准 stdio（17）；18 再接入真实终端。
- 19 与 20 可以并行：一个核对跨资源限额/错误/快照，一个核对组合退出屏障。
- 23 完成后，24、25、26 可以并行；27 只在三类最终原件均具备后判定。
- 这些说明不建立额外固定波次，最终以直接 blocker 及实际完成状态领取。
