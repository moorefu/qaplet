## Problem Statement

应用作者需要让 timer、原生任务、子进程和 stdio 在入口完成后继续协作运行。M1 已能显式推进 Promise jobs 和有界 Qaplet Event，但没有 OS 等待与唤醒、资源保活、可取消任务或完整的原生退出合同。将“入口完成”“暂无就绪工作”和“可以释放 Runtime”混为一谈，会导致提前退出、无限轮询、丢失最后一个完成或释放仍被后台使用的数据。

C Host 需要将 Runtime 接入自己的事件循环，也需要选择由 Runtime 主动等待。生产者不能访问 JS 堆，已接受原生操作不能因为业务队列满而丢失完成与回收责任。取消成功不能伪装成 syscall 已退出；CLOSED 不能被误当成所有 worker、句柄和 userdata 都已经不再使用。

跨平台应用还需要可靠的子进程 argv/env/cwd、stdio 背压、退出与 EOF 分离、终端模式恢复及明确的能力差异。现有 M0 I/O 探针与 M1 成绩不证明这些新增合同，维护者需要新输入、真实宿主和严格证据，才能发布 M2 支持声明。

## Solution

在单主 Context、固定 owner 的 Qaplet Runtime 上增加实例独立的 Scheduler、TimerHeap、Reactor、waker、可靠完成交接、有界 WorkPool、直接子进程和基础 TTY/stdio。以最小 qaplet:* 模块和版本化 C SDK 提供同一套能力，继续由 owner 显式 pump、run_once 或 run；SDK 不启动隐藏 JS 线程。

分开表示入口执行、循环保活、Runtime 生命周期和原生清理。保留完整 Promise jobs 检查点，在检查点之间对完成、timer、immediate 和业务事件有界轮转。业务事件沿用可拒绝的固定槽队列，原生操作在接受前取得完成及数据容量。

采用逻辑取消与物理退出分离、close 与 native quiesce 分离，以及最终 destroy 前的生产者撤下责任。保持 M1 ABI 和旧创建行为，以独立 M2 创建配置和快照显式启用新能力。CLI 与包外纯 C Host 共用产品合同，并通过主要原生目标、实际 64K 内核及约定长测形成新的验收闭包。

## User Stories

1. 作为 SDK 集成者，我希望旧 M1 创建入口和结构布局保持兼容，以便既有 C Host 可以继续使用新 SDK。
2. 作为 SDK 集成者，我希望显式启用 M2 并查询实例能力，以便不会把库支持误当成当前实例已启用。
3. 作为嵌入宿主开发者，我希望扩展创建失败不发布半成品并释放已取得资源，以便安全重试配置。
4. 作为嵌入宿主开发者，我希望每个 Runtime 仍只有一个固定 owner 和主 Context，以便所有 JS 访问保持线程归属。
5. 作为嵌入宿主开发者，我希望各 Runtime 独立拥有调度资源，以便一个实例的饱和和停止不会依赖另一个实例。
6. 作为嵌入宿主开发者，我希望 pump 保持不主动等待，以便在自己的循环中分步推进。
7. 作为嵌入宿主开发者，我希望 run_once 接受有限等待上限，以便等待 I/O 时仍能收回控制权。
8. 作为应用作者，我希望 run 持续推进保活资源，以便入口完成后 timer 和异步工作仍能运行。
9. 作为嵌入宿主开发者，我希望驱动返回原因、执行阶段和错误分开，以便区分空闲、等待超时、错误与停止。
10. 作为应用作者，我希望单独悬挂的 Promise 不制造虚假保活，以便无法推进的入口明确报告未完成。
11. 作为应用作者，我希望入口 DONE 不自动关闭 Runtime，以便继续处理已经建立的异步资源。
12. 作为生产者开发者，我希望显式取得和释放宿主保活令牌，以便未来投递仍有等待者。
13. 作为应用作者，我希望 unref 不等于取消，以便资源在其他工作维持循环时仍可执行。
14. 作为应用作者，我希望仅剩 unref 就绪资源时允许自然返回，以便后台资源不会意外维持程序存活。
15. 作为应用作者，我希望丢弃 JS 句柄不会隐式取消资源，以便关闭行为不依赖 GC 时机。
16. 作为应用作者，我希望 Runtime 可长期存活而单次执行仍有预算，以便持续应用不绕过执行期限。
17. 作为应用作者，我希望 Promise jobs 结算到完整检查点，以便回调之间不会破坏微任务及 rejection 语义。
18. 作为应用作者，我希望其他就绪类别有界轮转，以便持续就绪的单类工作不会独占检查点之间的调度。
19. 作为应用作者，我希望普通回调错误结算 jobs 后返回驱动，以便宿主决定是否继续运行实例。
20. 作为应用作者，我希望入口 rejection 和终止首因不会被重复或覆盖，以便可靠归因。
21. 作为应用作者，我希望能够创建及取消一次 timer，以便安排延迟工作。
22. 作为应用作者，我希望 interval 跳过错过的周期，以便恢复运行后不会突发追赶。
23. 作为应用作者，我希望 immediate 最早在注册调用栈之后运行，以便避免隐含同步重入。
24. 作为应用作者，我希望同 deadline 的 timer 和 immediate 有稳定顺序，以便结果可复验。
25. 作为应用作者，我希望 timer 参数严格校验，以便溢出和隐式类型转换不会改变调度意图。

## Implementation Decisions

### B01 — 基线、阶段范围与 ABI

- M1 已实现。其单主 Context、创建线程固定 owner、持久模块与全局环境、不可撤销 stop、有限预算、错误首因和旧创建模式继续有效；本规格扩展 M2 模式，不改写 M1 历史验收。
- 每 Runtime 独立拥有和计量调度资源及有界 WorkPool，worker 按需启动；不引入进程级共享任务池。非 owner 不操作 JS_*、JSValue 或 Context，一个 socket 不独占一个 OS 线程。
- 新增独立 M2 配置、创建入口和快照；保留全部 M1 结构布局、旧错误数值和旧创建入口行为。尤其不直接扩大嵌在旧结构中间的 limits，不复用旧 reserved 字段承载新语义。
- ABI 主版本沿用 1。新结构遵守显式大小、版本、受支持字段范围及未知非零字段拒绝规则；旧调用方缓冲区不能被新字段覆盖。实际原型、枚举编码与初始化宏由公开头文件统一落实，并由旧头文件消费者和新纯 C Host 验证。
- 库能力与实例已启用能力分开查询；旧模式不因库新增 M2 而自动取得线程、stdio 接管或新关闭语义。扩展创建失败返回空句柄，回收已取得的半成品资源；输入未接受时不改变既有执行结果。
- M2 提供 qaplet:timers、qaplet:work、qaplet:process、qaplet:stdio 的最小能力；继续保留 qaplet:events 和 qaplet:runtime。已声明内建仍计入模块额度，M1 模块身份、失败缓存、注册冻结、argv/cwd 快照与严格值桥不变。
- Scheduler 负责顺序、保活和退出；Reactor 负责 OS readiness/完成；WorkPool 负责阻塞原生工作；ProcessHost 负责创建与回收；stdio/TTY 负责流与租约。业务层 FS、DNS、Node 和网络语义不挤入 Loop。
- 本规格确定目标可观察合同，不把总体计划里的 C 伪合同直接当成已冻结 ABI。各 OS 的具体 backend 必须先完成真实探针，才可签发该平台的实现支持。

### B02 — 公开操作与线程、重入合同

下表的操作名表示合同角色；新增 C 符号和数据形状由实施头文件稳定表达，不另行改变产品决策。

| 操作 | 输入、输出与效果 | 权限 |
|---|---|---|
| 扩展创建 / 能力查询 | M1 配置加独立 M2 配置；完整句柄或空句柄；区分库和实例能力 | 创建线程成为 owner；全局只读查询可任意线程 |
| 注册 work 处理器 | 复制命名声明和有限参数；保留原生函数、userdata 引用 | owner，执行前；不支持替换或运行中注册 |
| eval / run_entry | 沿用 M1 入口、结果及选项；run_entry 是模块入口，不是循环驱动 run | owner，禁止危险重入 |
| pump | 不主动睡眠，有界推进已就绪工作 | owner |
| run_once | 有限 max_wait、有界调度轮次；分别返回进度、返回原因和错误 | owner |
| run | 持续推进到自然空闲、普通错误或终止 | owner |
| timer / immediate / 资源 ref、unref | 创建、取消和修改保活属性 | owner；JS 接口在 owner 内执行 |
| 宿主保活令牌 | owner 创建；任意线程可释放并唤醒 | 令牌仍归属于存活 Runtime |
| work 提交 / 结果复制 / release | 复制输入、预留输出、返回任务；C 复制终态结果并释放 | owner；安全异步提交可在明确白名单回调中使用 |
| 任务取消 | 原子记录取消或已完成；不等同 syscall 已退出 | 任意线程，不直接执行 JS |
| Process / stdio / TTY 操作 | 受控创建、读写、观察、模式租约和关闭 | owner；取消走不触及 JS 的控制路径 |
| post_event / stop / wake | 复制业务事件、记录不可逆停止、发出唤醒提示 | 任意线程 |
| POD 查询 | 生命周期、阶段、原生清理、资源和操作状态 | 任意线程，不暴露 JS 指针 |
| close | 停止接收、释放 JS、保留 CLOSED 控制句柄与必要原生数据 | owner，当前无活跃驱动或用户回调 |
| quiesce | CLOSED 后推进原生回收，有限等待或仅检查 | owner，无用户 JS |
| destroy | 满足原生清理及宿主前置条件后最终释放 | owner，只最终释放一次 |

- 其余实例操作默认 owner-only。合法参数和 ABI、线程及重入、生命周期、句柄与容量分别检查；拒绝路径不运行 JS。
- owner 回调仅开放明确安全的异步提交与控制操作，及 M1 已允许的 setter、投递、stop、POD 查询；注册、求值、嵌套驱动、close/destroy 等仍拒绝。
- 整个 pump/run/run_once/quiesce 调用范围都受驱动重入保护，包括 phase 为 PENDING 或等待中的时段；不能只以 RUNNING 标志判断 BUSY。非 owner 的 owner-only 操作返回 WRONG_THREAD。
- HostNotify 不是上述可重入宿主函数：它不得调用 SDK、运行 JS 或阻塞。普通 thread-safe 不表示 signal-safe。

### B03 — 执行完成、循环保活与结果

- 入口 DONE、循环自然空闲、JS CLOSED、native quiescent 是四个不同事实。自然空闲只让驱动返回，Runtime 仍可为 OPEN，不自动 stop、close 或 destroy。
- Promise 本身不保活。入口仍 PENDING，完整检查点后又没有可推进工作的 ref 资源、已接受业务工作或宿主保活令牌时，自动驱动报告 UNSETTLED_ENTRY，不伪装成成功。旧非阻塞 pump 仍可返回 PENDING/progressed=0。
- 新 timer、任务和直接子进程默认 ref；unref 只解除自然退出责任，不取消资源。宿主等待未来投递须显式持有保活令牌。
- run 在完整检查点判断存活；已领取工作产生的 jobs 和已接受业务事件仍处理。仅剩 unref 就绪资源不单独维持 run；显式 pump/run_once 可以处理它们，但不为 unref-only 资源持续等待。
- 任务默认 ref 在 owner 完成结果交接、包括必要的 Promise 结算后解除，不能在 worker 仅发布原生结果时提前解除。当前检查点产生的 jobs 仍须结算。
- C Host 保留的终态结果，以及逻辑取消后仍在运行的原生任务，继续占对应容量但不继续保活。循环存活不能作为存储已释放的证明。
- JS 句柄被丢弃或 GC 不会隐式取消已注册资源；资源的 cancel/close/release 与 Runtime 关闭负责退出。JS work 结果交付后按任务合同回收原生结果，不依赖用户等待 GC。
- SDK get_result 保持最近一次完成执行的语义；下一次被接受的独立交付执行可以替换它，未接受调用和无进展空闲推进不替换。CLI 单独保存入口结果，不能为它改写 SDK 结果槽。

### B04 — 调度、微任务和 timer

- Promise jobs 优先推进到完整检查点；配额耗尽只交还宿主，跨 pump 延续同一检查点。jobs 未清空时不插入 timer、I/O 完成或业务事件回调，也不提前判定 unhandled rejection。
- 在完整检查点之间对内部完成、到期 timer、immediate、业务事件有界轮转，位置跨调用保留；各类别保持自身顺序。每次交付后先结算所产生的 runnable jobs，再领取下一回调。
- 无限 jobs 由累计执行预算终止；本规格不承诺无限微任务存在时仍能交付 I/O 回调，也不通过插入回调改变既有微任务合同。
- 同 deadline 的 timer 按注册接受顺序；immediate 按 FIFO。回调中新建的 immediate 最早下一轮领取，不在注册调用栈中运行。
- delay 接受有限、非负的安全整数毫秒；拒绝隐式转换、非整数和不可表示的 deadline。零延迟 timeout/immediate 不同步执行；interval 至少 1ms。
- interval 以原计划时间推进，错过多个周期只补一次，下一计划跳过已错过时段；取消阻止后续触发。回调返回值包括 Promise 不阻塞下一触发，runnable jobs 与 rejection 仍受检查点规则约束。
- 普通回调错误在原预算内结算 jobs 后向驱动返回，由宿主决定是否再次驱动。已发生副作用不回滚；终止错误后不再调度用户 JS。
- 默认每轮最多 256 jobs、32 个交付单元及 256 KiB I/O 推进；M1 业务事件仍受其原有 quota。新总额度不能放宽旧已声明限制。

### B05 — 等待、期限和执行账本

- Runtime 可以长期存活；M1 默认 30 秒是单次执行的绝对 CLOCK_MONOTONIC 期限，默认 100,000 是该执行累计 jobs/交付量，不是 Runtime 寿命或每 tick 可重置额度。
- 有活跃入口时，timer、完成及业务交付和其 jobs 共用入口账本；包括 TLA 等待原生结果及交还宿主的时间。入口结束后，每个独立交付及完整 jobs 检查点使用独立账本，跨 pump 延续。
- 纯等待及原生清理不凭空创建 JS 执行账本。per-execution 选项仍只能收紧实例执行限额。
- run_once 有就绪工作时不先等待，仅在没有就绪工作且需要继续等待时进入系统等待；等待受 max_wait、最近 timer 和活跃执行 deadline 的最小值约束。0 表示不主动等待。
- 本次等待耗尽是普通驱动返回，不触发 Runtime FAILED；执行期限或总调度量耗尽则永久 FAILED。返回原因、执行 phase、progressed 和稳定错误 code 分开表达。
- max_wait 是 SDK 主动等待的累计预算，多次唤醒不重置；它不承诺整个调用硬耗时，不强抢 JS/native 回调或析构。quiesce 和 CLI 清理等待同样遵守此区别。
- 调度使用单调时钟，不用墙钟。不同 OS 对系统休眠的计时行为须实测记录，不宣称一致；恢复后按读到的时间判断到期，interval 不突发追赶。
- 核心时钟失败或检测到倒退按不可恢复控制故障处理，不悄悄延长期限；创建/输入阶段不可表示的期限先拒绝，不污染已接受执行。

### B06 — 唤醒、业务队列和可靠完成

- wake 是可合并的重新检查状态提示，不是业务事件、任务完成或 JS 回调。多余通知允许无进展，不以通知次数计算业务量。
- 成功投递、原生完成、取消、宿主令牌释放及 stop 的状态发布必须使 owner 能重新检查；检查为空与真正睡眠之间不得丢唤醒。
- stop 独立于业务容量。业务事件仍完整复制、FIFO 接受；NO_HANDLER、超大载荷和 QUEUE_FULL 均拒绝新工作，不等待、不覆盖、不隐式重试，接受不等于交付。
- 原生操作在接受前取得独立完成记录和数据容量；完成、取消及回收不临时竞争业务槽，不要求应用注册 onEvent，也不因业务饱和丢失责任。
- 内部完成发布只处理原生记录；owner 才创建/释放 JS 值及结算 Promise。终止后只做原生回收，不强制兑现 JS 终态回调。
- 接受发布是确定的提交点。入队、取消或 stop 已发布后，后续不可恢复 waker 故障不把调用改成假拒绝；保留“已接受”返回，独立记录控制故障，由快照/驱动报告，遵守终止首因规则。
- 可选 HostNotify 在任意线程快速通知宿主自己的循环，允许合并和多余通知；不执行 JS、不重入 SDK、不阻塞。内部 waker 不依赖钩子正确工作，也不向宿主导出其等待 fd/HANDLE。
- 通知函数及 userdata 的保留期同时覆盖内部原生清理和外部在途调用；回调目标尚在使用时不能卸载或释放。

### B07 — 命名 WorkPool、任务结果与取消

- 执行前注册命名原生处理器，沿用 M1 首次执行/有效 pump 后冻结的原则。重复、替换及运行中注册拒绝；声明复制，函数代码和 userdata 不转移所有权。
- JS 获得任务对象与完成 Promise；C Host 获得 opaque handle，通过 owner 查询、复制结果及显式 release。任务输入在成功接受前完整复制，输出容量事先预留；超出声明输出上限只失败该操作，不扩容后假装符合额度。
- worker 只使用原生任务数据、受限输出和取消标记，不访问 JS 堆。完成交接不依赖临时新增业务槽或完成时分配。
- 每处理器默认最大并发 1，可显式提高但不超过池容量；宿主保证共享 userdata 线程安全。受处理器额度阻塞的任务不占 worker，也不阻塞其他可运行处理器。
- 排队取消后不启动；运行中接受取消只说明请求已记录，syscall 可能继续。使用协作标记和已验证 OS 取消，不用强制 pthread_cancel/杀线程越过未知资源状态。
- 取消与结果发布按同步接受顺序决定：取消先记录则为 CANCELLED，结果先发布则报告已完成；每任务至多一次终态交付。迟到结果只释放资源，取消不回滚原生副作用。
- C 只允许 release 已逻辑终结的记录；非终态返回 BAD_STATE。保留记录时重复取消幂等，完成已发布时返回已完成；release 后旧 token 的查询、取消及取结果明确为失效句柄。
- BUFFER_TOO_SMALL 报所需长度，不部分复制、不重跑任务；结果保留及物理执行未结束期间继续计费。release 或 JS 交付不提前释放仍被物理任务使用的数据。
- 新 work 的函数代码和 userdata 保留至 native quiescent；与旧同步 Host Module 的 close 返回边界分开。若同一 userdata 同时承担两种角色，须满足仍在使用它的较长保留期。
- 使用真实有界文件读取处理器贯通注册、JS/C 提交、复制、线程、取消、结果及清理验收；不因此交付完整 FS、DNS、KDF 产品 API。宿主处理器自行分配的外部资源不自动成为 SDK 堆硬限额的一部分。

### B08 — Reactor、资源身份与原生后端

- 优先 owner 同线程等待，P0 从 Cosmopolitan poll 起步；Windows Socket、Pipe、Console、进程 HANDLE 可以分路，统一归一化为 readiness/完成。
- 必须用真实探针确定等待、错误、关闭、HUP/EOF、非阻塞 connect、半关闭、取消及唤醒；不能把某平台 revents 数值或头文件声明当作跨 OS 合同。
- 需要辅助线程时受实例额度控制；不得每 socket 一线程或固定 10ms 短轮询空转。epoll/kqueue/IOCP 优化不是 M2 完成前提，也不形成另一套业务 ABI。
- 资源使用包含 Runtime 身份与 generation 的 opaque handle；不把 fd/HANDLE 或裸槽号作为身份。复用、unwatch、close 与事件领取有明确顺序，过时代次不得命中新对象。
- 代次耗尽停止复用该槽，不能回绕误匹配。M1 业务 token 保持应用自定义 uint64 数据，不承担 SDK 资源身份校验。
- readiness 不是业务操作成功；短读、短写、暂不可用及错误由端点状态机推进。无需求时不能因持续 readiness 形成忙循环。
- Runtime destroy 后所有指针别名无效；generation 不能用来安全检查已经释放的 Runtime 指针。

### B09 — ProcessHost、退出与句柄继承

- M2 只管理自己创建的直接子进程。spawn 使用显式文件路径；相对可执行路径以 Runtime cwd 解析，默认子进程 cwd 为 Runtime cwd。不搜索 PATH/PATHEXT，不隐式调用 shell，解释器需显式给出。
- argv/env/cwd 在接受前校验并复制，路径、参数和环境拒绝 NUL 及非法 UTF-8。Unicode、空格、引号、反斜杠与 shell 元字符必须保留参数边界。
- M2 创建时复制环境快照；未提供 env 时使用该快照，提供时是完整替换映射，不能混入之后的宿主环境变更。
- stdio 支持 pipe/inherit/ignore，默认三路 pipe。只继承明确授权的 stdio，内部 waker、任务文件、socket 和其他句柄不得泄漏；内部描述符传递不得导致额外授权或延迟 EOF。
- 分开报告直接子进程实际退出并 reap，以及受管理 stdio 结束/关闭。退出后仍允许读完输出；EOF 不是进程退出证明。
- ref 子进程保活到直接子进程回收及其受管理 stdio 结束。后代继承管道可能延迟 EOF，调用方可以显式关闭端点；inherit/ignore 不产生永远等待宿主标准流 EOF 的管道责任。
- 取消采用目标平台已验证的直接子进程强制终止并回收，不承诺温和信号、宽限期或优雅退出。保留实际 native exit/signal/error 事实，不伪造跨 OS 统一信号或退出码。
- 创建中失败、终止与退出竞争、stdio 失败、重复取消和 close 仍须收口句柄及直接子进程责任，不能将逻辑 CANCELLED 当成已经 reap。

### B10 — stdio、TTY 与字节合同

- C SDK 默认不接管宿主标准流，CLI 显式接入；实际区分 Console、TTY、pipe、文件和无效句柄，不从私有 Console 探针推断真实 stdin 类型。
- 借用端点不擅自关闭或修改共享状态；复制描述符不被假定能隔离全部状态。需要修改共享状态时必须有明确租约/授权，无法安全支持的接入明确 UNSUPPORTED。
- stdout/stderr 各自有序、分别拉取；不自动全量收集或无限积累输出。未消费时停止继续读取，形成背压。
- 每端点每方向最多一个未完成读或写，额外请求 BUSY。读取当前可用字节，不等到填满请求；EOF 与暂时无数据分别表示。
- stdin 写入先复制，完成和失败都保留实际已写量；OS 接受写入不等于子进程业务消费。正常结束写入与立即取消/关闭分开，调用方不能不看已写量就重试。
- pipe、文件及已支持字节流保留 NUL 和任意字节；不隐式解码。Console 只声明经过真实探针的 UTF-8 文本/VT 子集，不当作任意二进制管道，不用替换字符掩盖非法输入。
- TTY 模式由显式独占租约管理，保存原模式，正常释放、错误、stop 后原生清理和 close 路径幂等恢复；同一受管理终端拒绝冲突租约。宿主协调绕过 SDK 的修改。
- 尺寸可查询，变化通知可以合并为最新值。强杀或系统故障不承诺恢复；PTY/ConPTY 在本阶段作为真实设施，不公开完整创建 API。

### B11 — 生命周期、终止和两阶段原生回收

Runtime 生命周期沿用 OPEN / STOP_REQUESTED / STOPPED / FAILED / CLOSED，执行阶段沿用 IDLE / RUNNING / PENDING / DONE；原生运行、清理中及清理完成另行报告，不将它们折叠进一个错误码。

| 情形 | JS 与驱动 | 原生责任及允许的后续动作 |
|---|---|---|
| OPEN，入口 DONE 或循环空闲 | 可再次合法驱动，不自动关闭 | 已存在资源可继续存在，按 ref 规则决定自动等待 |
| STOP_REQUESTED | 立即拒收普通新工作；已领取执行协作退出 | 请求方只发布状态并唤醒，不在生产者线程遍历清理 |
| owner 确认 STOPPED 或观察 FAILED | 不再领取用户 JS；保留终止首因 | 立即撤销调度、取消任务并启动直接子进程终止/reap，不等 close 才开始 |
| 终止但尚未 close | JS 环境仍保留，不恢复执行 | 清理可以尚未完成；STOPPED 不是 native quiescent |
| close 返回 CLOSED | JS 引用、Context/引擎已释放，不运行剩余 jobs/finally | 保留控制句柄及仍被 worker/完成使用的数据，原生可能仍清理中 |
| CLOSED，quiesce 尚未完成 | 不运行 JS | 有限等待可重试；destroy 为 BUSY |
| CLOSED，native quiescent | 不运行 JS | 宿主撤下外部生产者并 join 在途调用后允许 destroy |
| destroy 成功 | 所有实例别名失效 | 不允许后续使用旧指针或 token 检查存活 |

- close 只在 owner 没有活跃驱动、JS/宿主回调时进行，允许 PENDING；幂等，不等待不可中断任务，不执行用户 JS 清理。旧同步 Host binding 仍保留到引擎析构完成及 close 返回。
- close 不提前释放内部执行者、输出缓冲、回收记录、waker 或 userdata 仍在使用的数据。已逻辑完成但物理未退出的记录继续计费，终态结果在 close 中失去对外可读责任，必要存储待原生退出后释放。
- quiesce 只接受 CLOSED。0 仅检查；有限等待累计预算到期返回仍待清理，不因此 FAILED，可再次调用；整个过程仅处理原生取消、完成、join/reap 及资源释放。
- native quiescent 要求内部执行者全部退出、必要完成记录回收和受管理操作资源释放；控制句柄自身保留到 destroy。不能证明退出就继续保留，不把挂起任务的数据强行释放。
- 清理错误独立报告并继续可行回收，不覆盖终止首因；后台回收及分配错误不得把 CLOSED 改回 FAILED。原生清理所需控制容量不能依赖业务队列空位或新的用户 JS 执行。
- 不可中断原生任务若永不退出，允许一直保留待清理状态；SDK 不承诺安全强杀任意线程或按时销毁。调用方需要进程隔离时由其外部监督者承担。
- 即使内部已 quiescent，SDK 仍无法推断未来外部调用。destroy 前宿主必须撤下外部生产者并等在途调用结束；通知钩子释放期也同时满足这一条件。

### B12 — 有限默认预算与计量

这些是用户确认的可配置工程默认值，不是性能测量值。配置 0 选择有限默认，创建后不扩容，不新增无限模式；无效、溢出或无法一致满足的组合在接受前拒绝。

| 项目 | 默认值 | 计量边界 |
|---|---|---|
| 引擎堆 / 引擎栈 | 64 MiB / 1 MiB | 沿用 M1；不等于线程栈和 RSS |
| SDK 原生存储 | 16 MiB | 包含 M1 存储、M2 注册/环境/队列/任务元数据及操作数据；源码缓存仍单独计量 |
| 单源码 / 模块源码缓存 / 模块数 | 4 MiB / 32 MiB / 256 | 沿用 M1，计入全部声明内建、host 与失败身份 |
| 业务事件 / 单事件载荷 | 256 槽 / 1 KiB | 沿用 M1，独立于可靠原生完成 |
| 桥接单值 / 同步宿主参数 | 1 MiB / 32 | 沿用 M1 |
| 单次执行期限 / 累计调度 | 30 秒 / 100,000 jobs 或交付单元 | 跨 pump 和等待累计 |
| Worker / 平台辅助线程上限 | 2 / 4 | 每 Runtime，worker 按需启动 |
| Worker / 辅助线程请求栈 | 各 1 MiB | 单独配置、计量，不藏入引擎栈 |
| 注册 work 处理器 / 每处理器并发 | 64 / 1 | 显式并发不超过池容量 |
| timer 与 immediate 合计 | 1,024 | 活跃或尚未安全回收记录都受额度约束 |
| Reactor 注册 / SDK 持有原生句柄 | 各 256 | 注册和实际持有 fd/HANDLE 分别计量，含平台内部所需资源 |
| 直接子进程 / 宿主保活令牌 | 32 / 64 | 每 Runtime |
| 在途或保留结果的 work、I/O 操作 | 合计 128 | 包含排队、运行、待交付和保留结果，物理未退出仍占额 |
| 操作输入、输出与 I/O 缓冲预留 | 合计 8 MiB | 是 16 MiB 原生总存储的子额度，不另加 8 MiB |
| 单次 work 输入 / 输出 | 各沿用桥接单值上限，默认各 1 MiB | 接受前复制及预留，仍受 8 MiB 和原生总预算共同约束 |
| 单次 I/O 块 | 64 KiB，且不超过桥接单值上限 | 每次接受和实际推进均有界 |
| 子进程 argv 项数 / argv、env、路径总字节 | 256 / 1 MiB | 编码后校验与复制；创建时环境快照也计原生存储 |
| 每轮 jobs / 交付单元 / I/O 推进 | 256 / 32 / 256 KiB | 完整 jobs 检查点规则优先，限额返回不重置账本 |
| CLI 原生清理等待预算 | 5 秒 | 主动等待预算，不是整个退出或析构的硬超时 |

- 接受前同时检查 count、预留字节、元数据及总存储；饱和立即拒绝新操作。容量不代表任意最大组合都能同时被接受，实际限制和平台能力可查询。
- 逻辑取消、C release 或 JS 交付不归还仍被物理执行使用的容量；C 保留结果继续占额。清理完成后操作资源回到基线，控制句柄本身无需在 destroy 前假装为零。
- OS 管理的线程栈、内核缓冲及宿主自行分配资源不自动纳入 SDK 堆硬额度；单独报告请求栈和线程数量，不将其伪装为 RSS/精确 CPU 预算。
- 小公开额度用于可复验负向验收。预检拒绝是操作错误；真正的 SDK/引擎分配拒绝仍永久终止，不能靠捕获异常或忽略分配返回继续运行。

### B13 — 错误、首因与诊断

- 容量预检、BUSY、失效句柄、取消、文件/进程/普通 I/O OS 错误只影响对应操作；普通用户回调异常按完整检查点向驱动返回，Runtime 可保持 OPEN。
- 执行预算耗尽、实际 SDK/引擎分配拒绝及不可恢复的核心等待/唤醒/时钟故障永久 FAILED；即使 JS 捕获也必须在 owner 边界观察独立终止 latch。
- 首次记录的 stop、预算、分配或控制终止原因保留，不按异常文本、墙钟或后续清理错误重新排序。stop 已先记录时，后来的 waker 故障仍可另报，但不替换首因。
- 新操作提供资源限额、CANCELLED、已完成及失效句柄等稳定类别，保留 native 错误域与原始数值；新数值由公开头文件表达，旧数值不变。普通 OS 返回 ENOMEM 不凭文字等同于 SDK 分配器已经拒绝。
- 诊断归调用方，沿用 M1 有界复制、短/零缓冲和安全错误提取；不运行 getter、Proxy 或 toString，不输出整份环境/载荷，不依赖完整异常字符串验收。
- 物理完成、逻辑结果、Runtime 生命周期、原生清理错误和驱动等待原因分别表达，不能用一个成功码证明全部已退出。

### B14 — 最小 CLI

- CLI 使用启用 M2 的统一 Runtime，保留 run 文件、eval 源码、help/version 及 M1 参数规则；入口完成后继续驱动 ref 资源，Promise 独自悬挂仍报告 UNSETTLED_ENTRY。
- 在入口完成时复制保存其结果，再继续后台交付；eval 仅在循环正常结束后输出一次可桥接结果，run 不打印模块 namespace。后台执行错误退出 1，不把后来 SDK 最近结果当成入口结果。
- 成功、执行失败、用法错误退出码保持 0/1/2；受支持的中断转协作 stop，按执行停止退出 1，保留对应诊断。
- CLI 显式接入标准流，并处理受支持 SIGINT/SIGTERM 与 Windows Ctrl+C。采用合适的 signal-safe 原生入口转交 owner；不得从 Unix signal handler 直接调用会加锁的普通 SDK stop。SDK 自身不安装进程级 handler。
- close 后原生清理主动等待预算 5 秒；到期报告未完成并退出 1，不伪造成功 destroy，不提前释放后台还在用的数据。若需进程结束来收口，相关数据保持到进程终止。
- 5 秒不强抢此前 close 中的任意 native 析构或用户原生代码；外部 supervisor 超时只能签发未完成/失败。不可捕获强杀不进入终端恢复保证。

### B15 — 可观测性

- 扩展原生 POD 快照公开实例能力、有效限额、生命周期与执行阶段、驱动进度、原生清理状态和终止/清理原因。
- 至少公开各资源当前量/峰值、任务排队/运行量、预留字节、I/O 字节、wake 及取消/丢弃计数；累计计数饱和，不回绕。
- 不暴露内部 JS、函数或原生存储指针；关闭后的 POD 查询继续使用保留控制句柄，不触发 JS 或重建已释放状态。
- CPU/RSS/延迟可作为标明 OS 来源与测量方式的观测，不伪造全平台支持、统一精度或未经测量的性能阈值；M2 不需要 HTTP 管理面。

## Testing Decisions

### T01 — 已确认的测试边界与既有方式

用户已在 Q14、Q49 确认测试入口，并在 Q53 确认整体合同。本次直接采用这些边界，不新增访谈或重新申请确认。

公开产品测试从最小 CLI、仅消费供应 SDK 的包外纯 C Host 进入；JS wrapper 和 C 入口使用同一产品实现。优先复用 [M1 公开合同与包外消费者](../qaplet-m1/spec.md#testing-decisions)、[SDK 分发入口](../../docs/development/sdk.md)、[M0 原生 I/O 基线](../qaplet-m0/native-io-validation.md)和[严格证据方式](../../docs/development/evidence.md)，不为每个内部模块建立平行产品框架。

原生 backend 探针补足真实等待、取消、fd/HANDLE 复用、继承、Console/TTY 及字节差分。受控系统故障夹具覆盖不适合随机制造的 waker/时钟/分配/创建失败；故障夹具或构建须标明自己的输入与配方身份，不代替正常产品宿主证明。Probe 通过不自动等于公开 SDK 合同通过。

好测试验证公开状态、稳定错误、数据、可观察副作用、输出/退出及实际资源释放，不依赖私有布局、内部调用次数或完整异常字符串。竞态用明确接受结果、可控生产者/owner 交接及两种顺序复现，不用随机 sleep 猜顺序；时限只防测试挂起，不能代替产品取消及退出证明。

- [ ] **AC-07 · waker**：跨线程投递、完成、取消、令牌释放及 stop 能唤醒；检查前、检查后入睡前、已等待及清理竞争均无丢唤醒。重复通知可无进展，空闲进入真实系统等待，无固定短轮询。
- [ ] **AC-08 · 宿主通知**：真实宿主循环收到提示并用 owner 驱动，合并/多余通知不改变业务结果；内部等待不依赖钩子，钩子在途与释放 userdata 的交接可复验。
- [ ] **AC-09 · 业务队列**：维持 M1 完整复制、NO_HANDLER、超大拒绝、QUEUE_FULL、FIFO 及接受不等于交付；饱和时 stop 和内部完成仍能进展，未接受输入不产生副作用。
- [ ] **AC-10 · 完成容量与接受点**：小 count/bytes 额度在提交前拒绝，无部分接受；已接受完成不受业务满影响。强制接受后 waker 失败时仍报告已接受、独立控制故障，重试不能成为隐含协议。
- [ ] **AC-11 · 资源身份**：混用 Runtime、过时代次、实际 fd/HANDLE 复用、unwatch/close 竞争、迟到和重复完成都不能交付给新对象；代次耗尽不回绕误匹配。
- [ ] **AC-12 · WorkPool**：冻结注册、重复/运行中拒绝、实例隔离、有限 worker/处理器并发和可运行任务无全局阻塞；真实有界文件读取从 JS 与 C 走完整闭环，worker 不进入 JS。
- [ ] **AC-13 · 任务数据与 release**：提交后修改原缓冲不影响输入；输出边界、BUFFER_TOO_SMALL 重读、C 终态持有及 release、JS 原生结果回收符合计费；非终态 release 拒绝，失效 token 不读到新任务。
- [ ] **AC-14 · 取消竞争**：排队取消不启动；运行中逻辑取消不假装物理退出；取消先/完成先两种明确顺序都至多一次终态。迟到结果释放、默认 ref 在 owner 交接后解除，副作用不伪造回滚。
- [ ] **AC-15 · spawn 输入**：显式路径、Unicode/空格/引号/反斜杠/元字符 argv、cwd 与环境快照/完整替换、非法 UTF-8/NUL、容量及缺程序错误；不隐式搜索 PATH/PATHEXT 或执行 shell。
- [ ] **AC-16 · stdio 继承**：pipe/inherit/ignore 与默认 pipe 都实测；子进程不能继承内部 waker、临时句柄或额外描述符；覆盖内部传递元信息、创建中失败、EOF 延迟及清理。
- [ ] **AC-17 · 字节与背压**：任意 pipe 字节、NUL、短读写、部分写错误的实际字节量、双通道并发消费、慢消费者背压、同方向 BUSY、正常结束与立即关闭；暂不可用不能伪报 EOF。
- [ ] **AC-18 · 进程状态**：退出/reap 与 EOF 两种顺序、退出后未读数据、后代持有管道但无整树声明、ref 到管道关闭、重复 cancel/close、强制终止及真实 reap；不只检查 Promise 已拒绝。
- [ ] **AC-19 · 标准流与 Console**：真实 stdin 的 Console/TTY/pipe/文件/无效类型接入；SDK 默认不接管，借用不擅自改变共享状态，不安全方式明确拒绝。Unicode、分块文本、非法字符和原始 pipe bytes 不混用判据。
- [ ] **AC-20 · TTY 租约**：私有 PTY/ConPTY 的模式读回、冲突拒绝、尺寸/resize 合并；正常、错误、stop 和 close 均恢复并核对原模式、关闭资源。强杀路径保留实际限制，不能写成恢复成功。
- [ ] **AC-21 · 预算与计量**：同时验证各 count、8 MiB 子额度、16 MiB 总额度和线程栈边界；逻辑取消/C 保留结果仍收费，物理退出后归还。使用小公开限额，不靠私有分配次数，控制句柄和外部 OS 缓存不伪报为零。
- [ ] **AC-22 · 错误与首因**：普通 OS/回调错误后可复用；实际分配拒绝即使被 JS 捕获仍失败。stop、期限、分配和控制故障以两种接受顺序验证首因，清理诊断、零/短缓冲及安全异常提取独立正确。
- [ ] **AC-23 · 终止即启动取消**：满业务队列和等待中 stop 仍可接受；请求方仅发布/唤醒，owner 确认 STOPPED/FAILED 即取消未领取调度和原生工作、启动 child 回收。无需等待 close 才开始，也不再执行用户 jobs。
- [ ] **AC-24 · 两阶段关闭**：PENDING/STOPPED/FAILED close 幂等，JS 已释放而 native 仍待清理；0/有限 quiesce 可重试且不运行 JS，CLOSED 不复活，未清理 destroy BUSY。覆盖 work userdata、HostNotify、外部生产者 join 及永不退出任务的安全保留。
- [ ] **AC-25 · CLI**：保存入口结果后继续 ref 资源，eval 输出一次、后台错误非零；受支持信号/Ctrl+C 经安全入口 stop，终端恢复。5 秒清理等待耗尽报告未完成，不伪造 destroy；外层 timeout 永远不是产品通过。
- [ ] **AC-26 · 原生 backend**：在实际 OS 验证 poll/readiness/error/HUP、非阻塞 connect/半关闭、Socket/HANDLE/Pipe/Console 分路、取消及 waker。头文件、交叉编译或已有私有终端成功不替代本次真实探针。
- [ ] **AC-27 · 生命周期和长测**：满足各目标约定循环次数与混合异步、Linux/Windows Full 的 10,000 次及 1 小时交替负载；操作资源回基线，不能随次数累积，无 UAF/死锁/无界排队，空闲真实等待。
- [ ] **AC-28 · 证据与回归**：M1 当前公开合同、包外 C 消费和相关 M0/Cross/Full 继续通过。新增 catalog、配方/产品/SDK/宿主/原件身份准确绑定；缺项、旧输入、错误摘要、重复/矛盾报告、必需 skip/fail 或外层超时不能聚合为通过。

### T03 — 平台、次数和 CI 门槛

| 目标 | 必需产品与 OS 合同 | 最低循环/长测 |
|---|---|---|
| Linux x86-64 native | 全部适用公开正负合同、真实 backend、M1 回归 | 1,000 次生命周期 + 100 次混合异步；Full 再做 10,000 次混合生命周期及 1 小时 idle/负载/取消交替长测 |
| Windows x86-64 native | 全部适用公开合同、Socket/HANDLE/Pipe/Console、Ctrl+C、继承和取消 | 同 Linux x86-64 |
| macOS x86-64 native | 全部适用公开合同、backend/stdio/TTY/进程差分 | 1,000 次生命周期 + 100 次混合异步 |
| macOS ARM64 native | 同上，记录实际执行架构及 translation 状态 | 1,000 次生命周期 + 100 次混合异步 |
| Linux ARM64 native | 全部适用合同，实测 kernel/页大小 | 1,000 次生命周期 + 100 次混合异步 |
| Linux ARM64 实际 64K 内核 | 当前产品合同、backend 及相关深层 ABI；原生优先，固定完整系统 guest 补缺 | 1,000 次生命周期 + 100 次混合异步；不得复用旧输入成绩冒充 |

- 生命周期覆盖 create、close、quiesce、destroy；混合异步包含实际资源创建、完成、取消、错误及清理，不以无资源空循环代替。Full 增强项必须作为单独可核对成绩，而非用计划参数冒充实际次数。
- 本地 Linux Fast 先运行完整功能与负向合同；各纵向改动及时执行适用 Cross，敏感源码、SDK、工具链和 CI 改动继续提升现有 Full。最终 M2 完成要求上表全部必需目标/清单通过，不能推迟到发布时补。
- ARM64 64K 必须在真实 65536 页内核运行；完整系统 QEMU 固定 machine/CPU/QEMU/TCG/kernel/config/rootfs，记录 guest 实测值。qemu-user 不替代实际内核，TCG 不外推物理性能。
- 空闲硬合同是没有工作时进入真实系统等待、无周期性短轮询；记录 idle CPU/RSS/延迟的来源与实际值，不编造全平台统一性能阈值。系统休眠行为按平台观测，不签发未测的一致性能力。
- 24 小时发布 soak 继续属于 M8，不因 M2 的 1 小时长测通过而宣称完成。

### T04 — 构建分发与证据连续性

- 构建 APE、静态 SDK 及包外消费者的产品构建统一在 Ubuntu；其他目标消费供应制品。相同 APE 字节跨宿主验证；SDK 的目标 archive/slice 分别标识，不能宣称所有目标是一份相同原生 archive。
- 复用固定输入、主仓库缓存和既有 producer/consumer 方式；产品、SDK、loader、provider 原 ZIP、源配方和执行日志分开绑定。新 M2 配方取得新证据，保留 M0/M1 旧成绩原范围。
- 严格聚合只读消费显式选择的原件，报告 M2、M1/M0 回归及 required/optional gaps；预检、探针、构建成功、计划和真实产品执行分别报告。
- 必需目标/用例缺失、failed、skipped、not_run、中断或超时均不通过；平台差异必须有明确能力及真实观测，不能用笼统 unsupported 跳过已经承诺的必需合同。
- 报告保留 OS/kernel/CPU/页大小/执行方式、实际命令、时间/次数、stdout/stderr/退出、资源清理事实及错误历史；受控故障和正常运行身份分开。关闭超时或外部 supervisor 强杀不能变成“stop 成功清理”的证据。
- 原 ZIP 长期镜像仍是独立发布门禁；本规格及未来 M2 验收均不自动签发 release-ready。

## Out of Scope

- 完整 node:*、process.nextTick、beforeExit/exit 钩子、Node 事件阶段兼容、CJS/package resolver、完整 FS/Buffer/Stream/readline/keypress/终端渲染，继续归 M3。
- TCP/DNS 产品 API、TLS/HTTP/Fetch/SSE/WebSocket，继续归 M4；M2 原生 socket 探针不等于已交付网络产品能力。
- 完整进程树/进程组清理、detached、IPC、统一跨 OS 信号兼容、温和终止及宽限期；M2 只强制终止并回收直接子进程。
- 对外完整 PTY/ConPTY 创建 API；它们在 M2 是受控真实验收设施。
- epoll/kqueue/IOCP 强制优化、每连接线程、隐藏 JS 执行线程、全局共享 WorkPool。
- 任意 native/syscall/GC/析构硬抢占、强杀 worker 线程、回滚外部副作用、stop/close 固定硬延迟、释放后旧 Runtime 指针安全检测。
- RSS 硬限额、精确线程 CPU 计费、未测的跨 OS 休眠一致性、全平台统一性能阈值。
- 24 小时发布 soak、网络并发长测、发布供应链门禁完成及 release-ready，仍由对应后续阶段验收。
- 应用业务、服务管理、SCM/应用私有 Job/watchdog，不引入 Qaplet Core 主线。
- 本次规格发布不创建实施票、不修改产品或 CI 实现，也不把新规格标为已验收。
