## Problem Statement

嵌入宿主需要通过稳定的 C 接口创建 Qaplet Runtime、运行源码模块、接收工作线程提交的数据，并在正常、错误、停止和资源不足时可靠关闭。当前微型 Host 仅验证固定 ESM/Promise fixture，缺少统一生命周期、公开值桥、文件模块身份、预算、线程拒绝和关闭合同，宿主尚不能据此构建可复用的嵌入应用。

CLI 用户需要与嵌入宿主得到相同的模块解析、Promise 完成、错误和预算行为。若各入口分别实现加载与执行，或把队列暂时为空当作入口完成，将产生状态漂移、TLA 悬挂和错误退出；若跨线程直接访问 JS 或将入队成功当成交付完成，还会造成资源失效和停止竞态。

维护者还需要区分已有 M0 证明与正式 M1 的新增合同。现有 pinned 输入和分级证据可复用为基础，新 Runtime/SDK 的结果必须由新构建、纯 C 消费者和实际宿主执行证明；M2 的 OS 调度能力及发布前镜像门禁仍保持原阶段边界。

## Solution

建立统一的单 Context Qaplet Runtime、源码 ESM 加载与缓存、owner 驱动的执行器和版本化 Qaplet Embed SDK。公开生命周期与执行阶段分开，使用显式 pump 推进 Promise jobs 和固定槽事件，向调用方返回可辨别的进度、结果和错误。

SDK 提供实例创建、宿主模块注册、Script eval、模块运行、分步推进、结果复制、POD 投递、协作式停止、状态查询、幂等关闭和最终释放。最小 CLI 使用同一套 factory、loader、执行器和预算。SDK 数据桥及事件只交接明确类型与复制数据，所有 JS 操作留在创建实例的 owner thread。

采用已确认的有限预算、固定模块身份与失败缓存、不可撤销 stop，以及 close/destroy 分离合同。由 Ubuntu 产生 CLI、静态 SDK 和纯 C Host 制品，Linux Fast、主要宿主 Cross 及相关 Full 运行新增合同，沿用现有输入身份、分发和原始证据规则。

## Implementation Decisions

### 基线、交付与模块职责

- 继续消费统一 v3 的 pinned 输入，目标 QuickJS 为 `2833510432045f72915919cef680ba59e5153b16`，cosmocc 固定为既有 Run `41169443573` / Artifact `13031425078`。每次使用仍复核输入，保留既有 ARM64 overlay 和旧成绩的原适用范围。
- 建立统一 Engine Factory、执行驱动、模块运行时、SDK 门面、受计量存储与 CLI 适配；CLI 和 SDK 共用同一套模块、资源、错误和生命周期规则。
- Engine Factory 管理主 Context 与所有 JS 引用；执行驱动负责进度、jobs 检查点、预算与终止；模块运行时负责规范身份、源缓存、宿主声明与失败记录；SDK 门面负责 ABI、线程权限、类型和调用方缓冲区。
- 交付最小 CLI、静态 Qaplet Embed SDK、公开 C 头文件、纯 C Host 示例、能力/默认额度声明与对应证据。公开 SDK 不依赖裸 JSContext、JSValue 或私有引擎头文件。
- 本规格冻结操作语义、输入输出、状态、所有权、默认值及验收。实际 C 声明与枚举数值由实现的公开头文件稳定表达，并由纯 C 消费者验证，不另开产品决策。

### 公开操作合同

以下名称表示公开操作，不规定内部布局。每次输出结构和诊断缓冲区仅在本次调用中由 SDK 读写，不由 PENDING 保留。

| 操作 | 输入与输出 | 线程和主要条件 |
|---|---|---|
| ABI/能力查询 | 支持版本、结构能力、已实现能力与有限配置说明 | 任意线程，不依赖 Runtime |
| create | 版本化配置、argv/cwd 基准与额度；成功返回完整不透明 Runtime，失败返回空输出并清理部分初始化 | 创建线程成为 owner，半成品不得公开 |
| register_host_module | 复制模块名、导出声明和常量；函数指针与 userdata 保持宿主持有 | owner；首次 eval/run_entry/pump 前；重名或锁定后拒绝 |
| eval | Script 源码、可选的显式绝对 file base URL、只能收紧的执行选项；输出执行进度 | owner；无其他活动执行；不包装成 CJS/ESM |
| run_entry | 文件入口或其显式规范身份、只能收紧的执行选项；输出模块执行进度 | owner；通过统一模块注册表执行，不直接按相同文件名反复新建模块 |
| pump | 推进当前执行或空闲事件，输出阶段、是否推进与本次诊断 | owner；受本轮及累计预算约束，不睡眠、不忙等、不启动隐藏线程 |
| get_result | 读取最近完成执行的稳定结果；标量直接复制，字符串/字节复制到调用方缓冲区 | owner；不重新执行或隐式转换 JS；容量不足报告所需长度 |
| post_event | 事件类型、关联 token、长度及内联 POD 字节；成功代表数据已经复制并接受 | 任意线程；句柄存活、普通工作仍可接收且 JS 接收函数已注册 |
| request_stop | 接受不可撤销停止请求；重复调用无副作用成功 | 任意线程；独立于业务队列，不访问 JS 堆 |
| POD 快照 | 生命周期、执行阶段、有效额度、公开统计与首次终止原因 | 任意线程；复制受同步保护的 POD，不调用 JS API |
| 返回值 setter | 为当前宿主回调同步复制一个有标签返回值 | 仅当前 owner 宿主回调中有效 |
| close | 停止接收并关闭执行资源，保留 CLOSED 控制句柄；附加关闭错误单独报告 | owner；当前没有执行 JS/宿主回调，允许 PENDING；幂等 |
| destroy | 最终释放 CLOSED 句柄及同步存储 | owner；宿主已撤下生产者并等待在途调用结束；只最终释放一次 |

### Runtime 生命周期、执行阶段和重入

- 每个 Qaplet Runtime 仅有一个存活的主 Qaplet Context，owner 固定为创建线程，不提供迁移或公开 Context 句柄。新环境通过新 Runtime 获得。
- 全局对象、词法绑定与模块状态跨求值保留。重复全局 Script 声明导致的正常语法错误按 JS 异常处理，不暗中清空环境。
- 一次执行账本对应 eval、模块入口，或空闲期由事件启动的独立执行。已有入口/Script 活动时，事件计入该账本；空闲事件及其可运行 jobs 自成账本。Runtime 同时仅有一个活动执行，PENDING 时新 eval/run_entry 返回 BUSY。
- 生命周期与执行阶段、结果 code 分开。执行阶段为 IDLE、RUNNING、PENDING、DONE；PENDING/IDLE 不是错误。DONE 可以携带普通执行错误，不能据此推断 Runtime 永久 FAILED。

| 生命周期 | 含义 | 后续允许行为 |
|---|---|---|
| OPEN | 实例创建成功，尚未永久终止 | 按执行状态注册/运行/pump、合法投递、查询、stop、close |
| STOP_REQUESTED | stop 已接受，普通接收闸门关闭，owner 尚未确认 | owner 到检查点确认停止或直接 close；查询、重复 stop |
| STOPPED | owner 已确认停止，不再执行用户 JS | 查询、close、重复 stop |
| FAILED | 首次终止原因为执行期限、总调度量或实际分配拒绝 | 查询、close、重复 stop |
| CLOSED | 执行资源释放，控制句柄仍存活 | 查询、重复 close/stop，满足宿主前置条件后 destroy |

- 非 owner 的受限实例操作在访问 JS 前拒绝。宿主回调内只允许返回值 setter、post_event、request_stop 和 POD 快照；其余重入返回 BUSY。全局只读 ABI/能力查询不需要实例。
- Runtime 生命周期、执行进度及注册锁定分别表达，不能用 OPEN 推断“现在可开始另一项顶层执行”或“仍允许注册”。

### 执行完成、pump 与结果读取

- eval 按 Script 语义执行，只自动等待实际 Promise；不隐式读取或吸收任意 thenable。其他对象、函数或不支持的值不能隐式 stringify/JSON 转换。
- run_entry 执行源码 ESM 并等待模块入口完成；只报告完成状态，不将整个 namespace 当作 SDK 返回值。
- 成功要求入口结果完成且相关可运行 jobs 结算完。jobs 为空而入口 Promise 未完成时仍是 PENDING；业务事件队列清空不是入口完成的必要条件。
- pump 优先运行 jobs；若 jobs 因配额尚未结算完，交还宿主，暂不插入下一事件。完成检查点后才能领取下一事件，每轮遵循有限 jobs/事件配额。
- 没有就绪工作且入口未完成时，SDK 返回 PENDING 并报告未推进，由宿主决定何时再次调用。owner 不被 SDK 隐藏唤醒，累计期限仍继续经过。
- 未处理 rejection 通过添加/移除记录跟踪，在完整 jobs 检查点判定。同一检查点结束前安装处理器可消除记录；配额耗尽且仍有 jobs 时不提前下结论。入口 Promise 的失败只报告一次。
- 普通 JS/模块或事件执行错误只使当前执行失败，已经发生的修改不回滚；可运行 jobs 仍在原预算内结算，之后允许再次执行。不可据此承诺取消任意用户 Promise 或撤回 native 副作用。
- get_result 的已完成结果保持到下一次被接受的独立执行或 close。未接受的新调用只写本次错误，不清除旧结果；容量不足可重试，不重新执行 JS 或转换值。空闲事件返回值被忽略，其结果只承载执行完成/错误，不承诺应用返回数据。

### 文件模块身份、缓存和元信息

- 模块依赖只接受显式相对 specifier、绝对 file URL、已注册 host 模块与已声明的 qaplet 内建模块。入口还接受本机绝对/相对 OS 路径，入口相对路径使用创建 Runtime 时固定的 cwd。
- 相对 import 基于导入模块；内存 Script 的相对动态 import 需要显式绝对 file base URL。没有基准时明确拒绝，不使用隐式变化的进程 cwd。
- 文件 realpath 后以规范绝对 file URL 为身份，只读取普通文件。相同规范身份只求值一次；首次确定的解析身份、加载源码与失败记录保持到 Runtime 关闭。实现须独立维护统一注册表，不能把相同文件名的原始引擎 Eval 当作缓存。
- 已有规范身份的加载、链接、求值失败保存失败，不在原 Runtime 热更新/重试；修复文件后创建新 Runtime 验证。无法规范化的请求只报告失败，不创建模块记录。成功加载的其他模块与部分模块图不自动回滚。
- 显式 .js、.mjs 和无扩展名文件按 ESM 源码处理；.cjs、JSON、WASM、字节码和动态 native 库明确 unsupported，其他扩展名不猜测。不猜测后缀、目录入口或 package。
- 拒绝 query/fragment、非空 file authority、路径 NUL、编码后的分隔符、UNC 和设备路径。Windows 本地盘符大写，路径大小写依据 OS realpath，不整体转小写。硬链接按不同规范 URL 处理，不承诺 inode 去重。
- import.meta.url 初始化为模块规范身份；main 在首次实例化时按是否显式 run_entry 根初始化，随后随缓存保持。已作为依赖加载的模块后来作为入口运行，不重新求值或改写 main。
- 上述身份规则不是 OS 沙箱，不承诺防御宿主并发换文件或隔离同用户权限。

### Qaplet Host Module 与类型桥

- Qaplet Host Module 使用 host: 命名空间，声明常量和同步 C 函数。首次 eval/run_entry/pump 锁定注册；重名拒绝，无替换/注销。qaplet 内建命名空间保留给已声明能力。
- SDK 复制模块名、导出声明、常量和声明中的字符串/字节；宿主保有函数代码及 opaque userdata，至少存活到 close 返回，SDK 不擅自释放。
- 桥接类型限定 undefined、null、bool、double、精确的有符号/无符号 64 位整数、UTF-8 字符串和字节数据。double 对应 Number，64 位整数对应 BigInt，不能经过 Number 导致精度丢失；超出支持整数范围明确拒绝。
- 任意对象/函数不隐式转换；字节值只接受可安全复制的 Uint8Array。路径/模块名禁止嵌入 NUL，普通字符串用长度表达并允许 NUL。
- SDK 输入严格验证 UTF-8；输出拒绝不能合法编码的孤立 surrogate，不静默替换或当作合法 UTF-8。不能直接依赖引擎默认的宽松输入或 WTF-8 输出。
- 回调参数仅借用到当前回调返回；宿主保留数据必须自行复制。返回值 setter 在回调期间同步复制输出，不保存回调栈或宿主临时缓冲区指针。
- 成功回调没有设置返回值时为 undefined；重复 setter 拒绝并保留第一次值，回调外使用拒绝。宿主函数普通失败转成带稳定 code 的 JS Error，可被 JS 捕获；实际分配拒绝仍按永久终止规则处理。
- 复杂对象和异步协议通过 JS 包装及 POD 事件组合，不扩展稳定 SDK 为任意 JS 堆访问接口。

### Qaplet Event、固定槽队列与接收函数

- 预分配固定槽，事件包含 uint32 type、uint64 关联 token、长度和有界内联字节。队列不持有外部指针、JS 引用或析构函数；所有入队成功的数据已经复制。
- type 在 JS 中为 Number，token 为不由 SDK 解释的 BigInt，0 合法。事件交付时载荷为拥有独立存储的 Uint8Array，宿主原始缓冲区后续修改不影响已接收数据。
- qaplet:events 提供 onEvent(fn)，由 owner JS 注册一次，之后替换/注销拒绝。此窗口独立于 C 宿主模块注册锁定；入口可以先注册接收函数，再通过 TLA 等待事件。
- 未注册时 NO_HANDLER；载荷过大明确拒绝；满队列 QUEUE_FULL，不等待空位、不覆盖旧事件、不自动重试。失败完全未入队，不接受部分载荷。
- 成功事件按入队接受顺序 FIFO，多生产者并发的顺序由实际接受顺序决定。成功只代表已接受，不包含交付确认；需要确认时由应用建立协议。
- owner pump 调用接收函数；其返回值不被等待，返回 Promise 的未完成状态不阻塞下一事件。它产生的可运行 jobs 正常结算，后续未处理 rejection 使用同一检查点规则。
- 已有顶层执行中的事件计入其账本；空闲期每个事件及其可运行 jobs 单独记账，跨 pump 不重置，完成检查点后才领取下一事件。普通事件异常遵循当前执行失败与复用规则，已领取事件不重试。

### 预算、计量与 GC

| 项目 | 默认值 | 计量边界 |
|---|---|---|
| 引擎堆 | 64 MiB | 引擎 backing allocations，自 Runtime 首次分配起执行，不是进程 RSS |
| 引擎栈 | 1 MiB | 引擎栈检查，不约束任意宿主 C 栈使用 |
| SDK 原生存储 | 16 MiB | 队列、注册表、rejection、诊断和桥接副本；源码缓存单独计量 |
| 单份源码 | 4 MiB | 实际源码字节，分配/编译前检查 |
| 模块源码缓存 | 32 MiB | Runtime 中缓存的模块源码，重复命中不重复收费；Script eval 不累计进入 |
| 模块数 | 256 | 内建、已注册 host、文件及已有规范身份的失败记录 |
| 事件队列 | 256 槽 | 待领取固定槽 |
| 单事件载荷 | 1 KiB | 内联字节，复制前检查 |
| 单桥接字符串/字节值 | 1 MiB | 实际编码/载荷字节 |
| 单次宿主函数参数 | 32 个 | 回调参数数量 |
| 单次执行期限 | 30 秒 | 启动后的单调时钟期限，包含交还宿主的等待 |
| 单次执行总调度量 | 100,000 | jobs 与事件回调的累计执行量 |
| 单次 pump | 256 jobs、32 事件 | 本轮最多执行量，不是 Promise 排队深度 |

- 0 一律采用有限默认值，M1 不开放无限模式。实例容量初始化后固定，执行选项只能收紧实例执行上限。大小、计数和时间的加法、乘法及换算先检查溢出。
- 期限、总调度量以及独立事件账本跨 pump 保持；反复返回 PENDING 或立即再次 pump 都不能重置。期限在引擎中断点、owner 调度和宿主回调边界协作式检查。
- jobs 优先，尚未结算完就返回宿主，暂不插入下一事件。公开引擎 API 不提供精确排队条数上限，本规格只限制执行量并通过内存预算约束存储。
- 可预检的输入、载荷、模块/源码容量和桥接超限只拒绝本次调用；实际引擎或 SDK 存储分配拒绝记录为永久资源终止，即使 JS 捕获异常也不能恢复 OPEN。创建阶段失败清理后返回空句柄。
- 分配拒绝记录排除正常的零大小释放；允许非增长 realloc 保留原块，避免可选收缩制造人为失败。记录的含义是实际观察到的分配拒绝，而非“最终未捕获 OOM”。
- 无法独立识别的引擎栈错误或引擎内部大小保护错误仍归 JS_EXCEPTION，不匹配异常文本，不为分类新增引擎补丁。
- 保留引擎自动 GC，可在 owner 安全检查点回收；不每 pump 强制 full GC，GC 阈值不充当硬额度。parser/compiler、GC、任意 native 回调及 native 清理不承诺硬超时或固定停止延迟。
- 宿主 userdata、工作线程、外部分配存储和 OS/libc 内存不纳入这些堆额度。快照提供引擎当前/峰值用量、队列深度/峰值、事件接收/拒绝/消费/丢弃计数、有效额度及终止原因，不读取或暴露 JS 指针。

### 停止、首因和关闭顺序

- request_stop 是不可撤销生命周期请求，成功表示已接受，不表示 owner 已停止或资源已关闭。stop 不占用事件槽，即使队列满也能接受；M1 不提供可恢复 request_interrupt。
- stop、事件入队和 owner 领取按统一接受顺序判断。stop 接受后关闭普通工作接收；已领取事件算执行中，协作退出；尚未领取的不再执行。
- owner 到检查点后不再调度新的用户 JS。第一次记录的 stop、期限、调度量或分配失败为终止首因，不根据后续异常文本、最终返回值或事后时间重排。重复 stop 在 STOP_REQUESTED/STOPPED/FAILED/CLOSED 上无副作用成功。
- 普通 JS 错误不自动成为永久资源终止；后续真正预算终止仍按其首次记录处理。终止首因和本次调用诊断分别保存，关闭附加错误不覆盖首因。
- close 在 owner 没有执行 JS/宿主回调时允许，包括 OPEN 中的 PENDING、STOP_REQUESTED、STOPPED 和 FAILED。close 停止接收并释放剩余事件及 owner 持有的 JS 引用，再释放 Context/Runtime 与 SDK 存储，最后发布 CLOSED。
- 关闭不额外运行用户 jobs、finally 或清理 JS；仍执行必要的 native 资源释放。引擎析构期间宿主绑定描述、函数代码与 userdata 保持有效，native finalizer 不得执行 JS。
- close 不等待生产者退出；控制句柄和同步存储保留到 destroy，重复 close 不再次执行资源清理。可检测的清理错误单独报告，仍继续其他清理。
- destroy 只接受 CLOSED，非 CLOSED 返回 BAD_STATE；owner 执行/回调内重入返回 BUSY。宿主必须先撤下生产者并等待在途调用结束；SDK 不承诺检测未来投递或释放后的指针。最终释放后所有别名均失效。

### ABI、错误类别和诊断

- ABI 主版本从 1 开始，版本化结构携带 struct_size/abi_version。只读写调用方声明且受支持的范围，支持零填充的兼容尾部扩展；不兼容主版本、缺失必需前缀、未知非零 flags/reserved 明确拒绝。
- 全局查询公开 ABI、结构能力和实际支持项；实例快照公开有效限额。仅实现并验收的能力可以进入支持声明，不以占位符或未来 API 冒充。
- 有效入参和 ABI 先验证，再验证适用线程/重入权限，再检查实例状态，最后检查接收函数与队列容量。正常错误路径不退出宿主进程，JS 异常不直接穿透 C ABI。
- 稳定错误类别至少包括参数、ABI、线程、BUSY、BAD_STATE、UNSUPPORTED、NO_HANDLER、QUEUE_FULL、载荷过大、模块解析/加载、JS_EXCEPTION、VALUE_TYPE_UNSUPPORTED、BUFFER_TOO_SMALL，以及期限/调度量/内存终止。进度 PENDING/IDLE 与错误 code 分开。
- 已接受执行的完成/失败通过结果接口读取；未接受调用的错误只写本次诊断，保留旧完成结果。BUFFER_TOO_SMALL 保留可重试的稳定结果与所需长度。
- 每次诊断由调用方持有独立版本化结构与缓冲区，无共享 last_error。消息有界，有空间时 NUL 终止，截断有标志；容量不足不丢失稳定状态码。
- 诊断不调用用户 toString、getter、任意 Proxy trap 或隐式类型转换，只附加安全可读的有界文本；无法安全读取时省略。默认日志遵循现有凭据/指针脱敏规则，不输出裸 native 指针。

### 最小 CLI 和内建模块

- CLI 提供 qaplet run 文件入口及分隔后的应用参数、qaplet eval 的显式 source，以及 help/version。run 使用 ESM，eval 使用 Script；与 SDK 共用 factory、loader、预算、结果与错误合同。
- run 不自动打印整个模块 namespace，eval 只打印可桥接结果，不为展示而隐式执行用户转换。
- qaplet:runtime 提供创建时固定、只读的 argv/cwd 快照；qaplet:events 提供一次注册的 JS 接收函数。两者纳入模块计数、能力声明和各入口的一致性验证，不据此宣称 Node process API 已实现。
- M1 CLI 没有外部事件生产者。入口未完成且无可推进工作时，立即报告 UNSETTLED_ENTRY，不忙等至默认期限。成功退出 0，执行错误/预算终止退出 1，参数错误退出 2。

### 必需的功能与负向验收

1. **实例与公开 SDK 消费**：纯 C Host 只依赖公开接口，实际链接 SDK 并运行 JS；多次求值保留状态，新 Runtime 获得新环境。创建配置无效、过小额度或初始化失败返回空输出并清理；失败后仍能创建新实例。
2. **状态与线程**：分别观察生命周期、执行阶段和错误；PENDING 时新 eval/run_entry 返回 BUSY，非 owner 的所有受限操作拒绝且无 JS 副作用。宿主回调内危险重入为 BUSY，允许的 setter/投递/停止/快照可工作。
3. **模块图**：用实际源码验证导出、依赖、动态 import、TLA、循环的已支持子集；缺文件、非法源码、链接/求值失败明确失败。通过副作用证明同规范 URL 只求值一次、symlink 规范化、加载后改文件及失败后修文件不改变原实例，新实例读取修正内容。
4. **路径与元信息**：覆盖相对基准和创建时 cwd、显式 base URL、普通文件限制、Windows 本地盘符与大小写、保留模块和 import.meta 首次值；覆盖 query/fragment、authority、编码分隔符、NUL、UNC/设备路径、unsupported 格式与未知 scheme 的拒绝。
5. **宿主注册**：验证声明/常量复制、host 命名、重复/锁定后注册拒绝、userdata 保留期和关闭清理时序；修正注册输入后可按仍开放的窗口重试，不发生部分声明接受。
6. **值与缓冲区**：覆盖标量、正负 64 位边界与超范围 BigInt、普通字符串 NUL、非法 UTF-8、孤立 surrogate、Uint8Array 和 unsupported 对象；修改/复用输入和回调临时缓冲区不改变已复制结果。验证参数/单值限额、setter 生命周期、重复 setter 和默认 undefined。
7. **完成结果**：真实 Promise 及非 Promise/thenable 的处理符合合同；get_result 的 BUFFER_TOO_SMALL 返回所需长度，可重读且不增加 JS 副作用。未接受调用保留旧结果，下一次被接受执行或 close 后不暴露失效结果。
8. **jobs 与 rejection**：完整检查点前补处理器不失败，跨 pump 配额不提前报告；真正未处理 rejection 和入口 Promise 失败正确报告一次。同步抛错、job 失败和事件异常后在原预算内结算可运行 jobs，再验证实例可复用且状态修改保留。
9. **无进展与 CLI**：SDK 未完成且 jobs 为空时 PENDING、未推进，之后由工作线程事件及 owner pump 完成；CLI 无外部生产者时立即 UNSETTLED_ENTRY。验证 run/eval 的共享行为、argv/cwd、help/version、成功/执行失败/参数错误的 0/1/2 退出码。
10. **事件桥**：onEvent 一次注册、未注册 NO_HANDLER、载荷深拷贝和独立 Uint8Array、uint32 type/uint64 token 精度及 0；单生产者及受控多生产者 FIFO。超大事件和满队列完全拒绝，不部分复制、不覆盖；领取后失败不重试，返回 Promise 不阻塞下一事件。
11. **执行预算**：用公开配置收紧额度，验证默认值、0、单次收紧和不允许突破实例上限。跨多个 pump、交还宿主等待和空闲事件账本验证期限/总调度量不会被重置；循环 JS 和无限 jobs 到预算后永久终止。
12. **存储与计量**：验证源码、模块、队列、桥接和原生存储计量边界；同缓存命中不重复收费，失败记录占模块额度，Script eval 不累计进模块源码缓存。预检超限不损坏实例；实际引擎/SDK 分配拒绝即使被 JS 捕获仍 FAILED。使用公开额度和受控产品负载产生拒绝，不依赖私有分配调用次数。
13. **停止并发**：在队列空、满、入口 PENDING、JS 循环和回调期间请求 stop；接受不依赖业务槽。用同步交接区分已领取/未领取事件，验证停止后拒收、剩余数据丢弃、已领取协作退出、重复 stop 和首因竞争。通过有副作用的 getter/toString/finally 验证诊断及停止清理不执行额外用户 JS。
14. **关闭与释放**：PENDING 可 close，重复 close 不重复清理；非 CLOSED destroy 拒绝。宿主按合同撤下生产者、等在途调用结束后释放，native 清理期间绑定仍有效；创建失败、普通失败、STOPPED、FAILED 和正常结束都覆盖关闭次序。保留首因并单独报告可检测清理错误。
15. **ABI 与诊断**：实际 C 程序验证不兼容版本、短结构、兼容零尾部、未知非零 flags/reserved、有效额度与能力查询；验证独立调用方诊断、短/零容量缓冲区、NUL 终止与截断标志。异常对象带 getter/Proxy/toString 时不产生报告副作用，错误 code 仍可获得。

预算/停止负向用例使用公开配置的小额度及时收敛；外部 supervisor 的进程时限只用于发现挂死，触发时表示用例未完成，不能直接作为 SDK 正确超时或停止的证明。通过条件必须包含产品返回的阶段、稳定原因和可观察的资源/副作用事实。

### 平台、循环和证据门槛

- 构建 CLI、静态 SDK 分发物和纯 C 示例均在 Ubuntu。其他宿主消费已供应制品，分别记录 SDK 包与目标组件身份；同一 APE 跨宿主比较同字节摘要，不用各宿主重新构建结果替代。
- Linux Fast 执行本规格完整正/负合同，创建—关闭—销毁至少 1,000 次；Cross 覆盖 Windows x64、macOS x64、macOS ARM64、Linux ARM64，每个目标至少 100 次并取得 SDK 关键行为证据。
- 保留当前敏感源码改动提升 Full 的规则。ARM64 64K 对变化后的输入与 SDK 关键合同取得实际内核证据，原生优先，固定完整系统 QEMU 可补缺；执行方式和实测页大小必须明确。qemu-user 或交叉编译不能替代该覆盖，也不把 TCG 当物理性能。
- 每个必需用例产生可审计的期望/实际结果、退出码、运行期限、原始 stdout/stderr、源/配方/SDK/APE 身份及真实 OS/CPU/kernel/page-size/loader/执行方式；本地与 CI 身份分别保留。
- 复用现有 producer、分发、native consumer 和严格证据回归；配方变化重新签发相应成绩，增加/变化的合同不能继承旧 M0 通过状态。证据消费者拒绝缺项、重复/冲突、错提交、错 SDK/制品摘要、篡改日志和错页配置。
- 必需目标或用例缺失、失败、skip、未完成都不签发对应通过。预检、命令计划、下载成功、空报告和旧样例成功不能作为 M1 产品验收。
