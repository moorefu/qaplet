Status: resolved

## 范围

落实用户确认的五项复盘建议：显式文本编码预检、受版本管理的证据保存/容量规划、选择与路径迁移、即时获取并消费下载引用、SDK/M1 小摘要。复用现有 public CLI、预检和回归；产品源码、57 个产品配方输入、原始证据与发布镜像决策保持原范围。

## 验收

- 证据工具与全部合同测试的 Path 文本 I/O 缺失编码时，现有 preflight/CI 拒绝；小型 Unicode fixture 在非 UTF-8 默认环境下保真。
- 保存 CLI 提供 plan/create/verify/restore/materialize；提前保留空间，严格校验路径、成员、摘要和元数据。失败保留源，既有不同文件不覆盖；校验收据不授权清理。支持历史 M1 tar.zst 和 Python 3.13 可用的标准归档。
- 路径派生从显式已接受配置、provider catalog 和保存收据出发，生成新配置及派生收据；只改变位置字段，原件不修改。实际 M1 迁移后通过原预检与严格重放。
- 逐件取得 provider 下载引用后立即下载；地址和凭据不写收据。失败尝试保留，已验缓存可离线复用，坏摘要/CRC 仍拒绝。
- summarize 支持 SDK、M1 gate 及严格报告，身份、计数、缺口和失败片段有上限，明确 evidence_verified=false。
- Ubuntu 日常检查、工具 CLI 回归及实际 M1 证据回放完成；明确报告平台和数据 opt-in skips，保持产品与评估器身份分离。
