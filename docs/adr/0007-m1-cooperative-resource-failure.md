# M1 使用协作式执行期限并固定资源终止首因

2026-11-02，用户确认 M1 采用从执行启动累计、跨 pump 不重置的单调时钟期限和总调度量，而不承诺精确线程 CPU 计费或 native/GC 的硬抢占。期限、调度量耗尽以及被分配器观察到的引擎/SDK 存储分配拒绝使 Runtime 永久 FAILED；普通 JS 异常在预算内结算可运行 jobs 后可复用，预检可发现的输入超限只拒绝调用。QuickJS 的 OOM 可以被 JS 捕获，中断也可能被 async 流程转为 Promise rejection，且这些操作不回滚应用状态，因此 Qaplet 独立记录首次终止原因、在 owner 边界检查，不从异常文字或一次引擎返回值推断可恢复性；默认值与计量边界见 [M1 设计 Q16/Q17/Q27/Q30](../../.scratch/qaplet-m1/design.md)。
